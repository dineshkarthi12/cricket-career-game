# Live PvP 3D asset manifest

Every 3D model and animation source considered for Live PvP, with its real
status. The same table is in code (`src/game3d/config/assets.ts`) and on the
**3D Lab** screen (`/pvp/lab`), which also loads and inspects any installed GLB
live in the browser.

Status values:

- **BUILT IN (PROCEDURAL)**: generated by this project's code.
- **DOWNLOADED AND VERIFIED**: the file is in this repository and the test
  suite parses it (`src/game3d/game3d.test.ts`).
- **REQUIRES MANUAL DOWNLOAD**: needs an account, accepting terms, or a host
  this build environment could not reach.
- **LICENSE NEEDS CONFIRMATION**: per-asset licences that must be read
  before use.

## What the game uses today

| Asset | Status | Licence | Used for |
|---|---|---|---|
| Procedural cricketer rig (`src/game3d/characters/rig.ts`) | BUILT IN (PROCEDURAL) | This project | Every player, keeper and umpire in the match scene |
| 30 procedural keyframe clips (`src/game3d/animation/clips.ts`) | BUILT IN (PROCEDURAL) | This project | All batting, bowling, fielding, keeping, celebration and umpire motion |
| Procedural stadium (`src/game3d/scene/Stadium.ts`) | BUILT IN (PROCEDURAL) | This project | Ground, pitch, stands, crowd, lights, scoreboard |
| Khronos **RiggedFigure** GLB | DOWNLOADED AND VERIFIED | CC BY 4.0, (c) 2017 Cesium | Test fixture for the GLB pipeline only, never shown as a cricketer |

**The rig.** One `THREE.SkinnedMesh` per player, bound to a 22-bone
`THREE.Skeleton`. Bones use Mixamo names: `Hips, Spine, Spine1, Spine2, Neck,
Head`, plus `Left/Right` + `Shoulder, Arm, ForeArm, Hand, UpLeg, Leg, Foot,
ToeBase`. Vertices near the elbows, knees and ankles are weighted across two
bones so the joints bend smoothly. Kits are vertex colours, and each team and
outfit shares one geometry.

**The clips.** These are hand-keyed in code, not motion capture: quaternion
tracks per bone, played and cross-faded by a `THREE.AnimationMixer`. In the
batting clips the clip keys the bat itself (`BatControl`), and two-bone arm IK
puts both hands on the handle. Left-handers get properly mirrored clips
(Left/Right tracks swapped and reflected), not a negative scale.

## Missing authentic cricket motion

No licensed motion capture of these could be obtained, so each is a
procedural clip:

- batting shots (drive, pull, cut, sweep, lofted drive, defence, leave, play and miss)
- fast and spin bowling actions, the run-up and release
- wicketkeeping, diving stops, catching and throwing
- umpire signals

Every one of these is labelled **Procedural keyframes** in the Lab. None is
presented as motion capture.

## Adding a licensed model or animation yourself

1. **Get the asset legally.** For example, sign in at https://www.mixamo.com/,
   pick a character, and download it as **FBX Binary, With Skin**. Download
   each animation as **FBX, Without Skin, 30 fps**. Read the site's current
   terms first.
2. **Convert FBX to GLB in Blender** (renaming the file is not a conversion):
   - File → Import → FBX, with *Automatic Bone Orientation* off.
   - Check the armature: Hips, Spine and the arm and leg chains must be
     present, and the character should face -Y in Blender (front view), which becomes +Z in
     three.js).
   - File → Export → glTF 2.0 → **glTF Binary (.glb)**, with *Include:
     Selected* and *Animation* (all actions) ticked, *Skinning* on, and +Y up.
3. **Place the file** in `cricket-career-game/public/assets/players/mixamo/`
   (for example `public/assets/players/mixamo/batter.glb`). Do not commit
   files whose licence forbids redistribution. Add the folder to `.gitignore`
   if the repository is public.
4. **Register it.** Add an entry to `ASSETS` in
   `src/game3d/config/assets.ts` with the `path`
   (`/assets/players/mixamo/batter.glb`), source URL, licence and status.
5. **Check it.** Open `/pvp/lab`. The *Imported model check* panel loads the
   file and lists its bones, clips and height. It also says whether the
   skeleton is compatible with the cricket clips: the `mixamorig:` prefix is
   stripped automatically, and missing bones are listed instead of being
   forced.
6. **Use its clips.** Map the imported clip names to animation states in
   `src/game3d/animation/states.ts`, and set the state's `source` to
   `IMPORTED` or `RETARGETED`. The Lab then shows the real source.

## Size and storage

The only committed third-party file is `RiggedFigure.glb` (50 kB). Keep large
models out of Git. Host them on a CDN or object storage and point `path` at
them, or use Git LFS.
